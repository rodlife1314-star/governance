## THE CORE CORRECTION

Pathfinder is not a software architecture.

It is a **spatial architecture of cognition**.

The distinction matters because it changes every decision that follows.

A software architecture asks: *how do we display more information?*

A spatial cognition architecture asks: *how do we reveal dimensional structure without overwhelming the observer?*

These are not the same question. They produce fundamentally different systems.

---

## THE OBSERVER IS AT THE CENTRE

In a conventional system, the user stands *outside* the system, looking at a dashboard.

The user is a consumer of information. The screen is the boundary.

In Pathfinder, the operator stands *inside* the field.

At the centre.

Everything else is arranged spatially around that centre — regions, layers, distances, domains. A navigable information topology, not a display surface.

```
NOT THIS:

  [Database] → [Processing] → [UI] → [User looking at screen]

BUT THIS:

                    DOMAIN A
                       │
  DOMAIN D ────── [OPERATOR] ────── DOMAIN B
                       │
                    DOMAIN C

  The operator is the reference point.
  Domains are positions in space, not tabs on a screen.
```

## THE NAVIGATOR PRINCIPLE

A pilot does not stare at every instrument simultaneously.

A diver does not study every molecule in the water.

A navigator observes the *shape of the environment* — and moves.

This is the model. The operator is a navigator, not a consumer.

Consequences:

- **Information is not displayed. Structure is revealed.** The system shows geometry, not data.
- **Compression is not loss. It is navigation-grade signal.** RAPIDS compresses 10 dimensions into one signal for the same reason a pilot's altimeter shows one number — not because the other data doesn't exist, but because the navigator needs shape, not raw pressure values.
- **Overwhelm is not an information problem. It is a geometry problem.** When an operator feels overwhelmed, the dimensional structure has collapsed into a flat display. The fix is not less information. It is the restoration of spatial depth.

## CRYSTAL BRIDGE — THE PROJECTOR

Crystal Bridge is not a router.

It is not passing work from one system to another.

It is acting as a **projector** — taking an unseen structure (the dimensional field the operator has navigated through) and rendering it into a visible, actionable dimension.

```
Field           → the unseen structure (existing but not yet visible)
Prism           → dimensional separation (RAPIDS + SIMON working)
Spectrum        → the revealed geometry (what the operator now sees)
Observer        → the operator at centre
Crystal Bridge  → the projection threshold — the only exit point
```

The bridge only opens from the inside. The operator has to have traversed the field — through AETHER, HERMES, SIMON, JEMMA — before the bridge becomes available. There is no shortcut to the bridge. Navigation is mandatory.

## THE OCTAGON BOUNDARY

The OCTAGON's 8-sided geometry is not decorative.

Eight faces, each a governance constraint. They define the *boundary* of the navigable space.

Not walls that trap the operator. Surfaces that make the space legible.

You can only navigate when you know where the edges are.

A navigator without boundaries is not free. They are lost.

OCTAGON gives the field its shape. Without it, the field is infinite and therefore unnavigable. With it, the field has a defined interior — and the operator knows when they are within it and when they are approaching an edge.

## THE OPERATOR'S SPATIAL STATE

The operator can be cognitively distributed — attending to multiple things simultaneously — without losing their position as the spatial reference point.

This is the normal condition of an operator at work.

The system does not demand the operator's full attention. It holds their position for them.

When they return to the field, the geometry is unchanged. The dimensions are where they were. The coverage report is still visible. The RAPIDS compression is still in the audit record.

**The centre is not a screen. The centre is the observer.**

Two feet on the floor. Everything else arranged around that.

---

## WHAT THIS MEANS FOR DESIGN

Every decision about the interface must be tested against this principle:

> Does this design assume the operator is a consumer of information, or a navigator moving through an information field?

If it assumes consumer → reject it.

A dashboard that displays everything simultaneously assumes a consumer. A display that collapses dimensional structure into lists and panels assumes a consumer. An interface that requires the operator to scroll through findings to understand their position assumes a consumer.

A navigator interface:
- Shows one thing at a time, but implies the structure behind it
- Compresses dimensional complexity into navigational signals
- Makes the operator's current position legible, not their distance from completion
- Gates forward movement — Crystal Bridge does not open until the geometry has been traversed
